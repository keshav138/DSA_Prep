## 1. `unordered_map` Basics

Used for both our stone-to-index lookup and our memoization table.

### **Declarations**

* **Simple:** `unordered_map<int, int> map;`
* **Nested (2D DP substitute):** `unordered_map<int, unordered_map<int, bool>> memo;`

### **Common Errors & Gotchas**

* **The Spelling Bee:** It is `unordered_map`, not `unorderd_map`. Easy to miss!
* **The `[]` Side Effect:** Accessing a key with `map[key]` **creates** that key with a default value (0 or false) if it doesn't exist.
* *Error:* Memory bloat or false "visited" flags.
* *Fix:* Use `map.count(key)` or `map.find(key)` to check existence first.


* **No Pair Support:** You cannot do `unordered_map<pair<int, int>, bool>` without writing a custom hasher. C++ doesn't know how to hash a `pair` by default.

---

## 2. Passing Data Structures to Functions

This is where most "Time Limit Exceeded" (TLE) errors come from.

### **The Gold Rule: Pass by Reference (`&`)**

Whenever you pass a `vector` or a `map` to a recursive function, you **must** use the ampersand.

```cpp
// Correct (Pass by Reference)
void solve(vector<int>& stones, unordered_map<int, int>& map) 

// Wrong (Pass by Value)
void solve(vector<int> stones, unordered_map<int, int> map)

```

* **Why it fails:** Passing by value creates a **full copy** of the data every time the function is called. In recursion, this means thousands of copies, leading to TLE or "Memory Limit Exceeded."

---

## 3. Memoization (The DP State)

The state is the unique combination of variables that defines a subproblem.

### **Key Errors**

* **Wrong State:** In Frog Jump, if you only used `idx` for memoization (e.g., `memo[idx]`), it would fail. You can reach the same stone at different speeds (), and those are different situations.
* **Initialization:** If using a `vector<vector<int>>` for memoization, always initialize it with a value that can't occur naturally (like `-1`).

### **Memoization Comparison Table**

| Structure | Best Used For... | Performance |
| --- | --- | --- |
| `vector<int>` | 1D DP (Climbing Stairs) | Fastest (Direct memory access) |
| `vector<vector<int>>` | 2D DP (Dense states) | Very Fast |
| `unordered_map` | Sparse DP (Frog Jump) | Fast (Good for large coordinate ranges) |

## 4. Integer Overflow

This is a silent killer in competitive programming.

* **The Error:** Adding a jump distance to a large coordinate and exceeding .
* **The Error:** Adding to `INT_MAX`.
* *Example:* `int right = INT_MAX + 10;` results in a very small negative number.


* **The Fix:** Use `long long` if the problem constraints suggest the coordinates or the sum of ways could exceed 2 billion.

---

## 5. Base Cases & Return Types

* **Infinite Loop:** If your jump distance  can be `0`, the frog sits on the stone and calls the function forever. Always ensure  for forward progress.
* **Boolean Logic:** If your function returns `bool`, remember that you can "short-circuit" it. As soon as you find one `true`, return it immediately. You don't need to check other paths.
